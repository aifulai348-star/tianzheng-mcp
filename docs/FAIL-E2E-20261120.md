## 二、这轮抓到的真 bug：多图纸下选错绘图视图

现象：`column.create` 直接失败，error `CAD could not acquire verified drawing-view focus`，状态 `unknown_outcome`。
排查：`_tmp/fail/dbg_focus.py` 列出主窗下 116 个可见子窗 —— CAD 里同时开着 6 张图，每张图都有自己的
`ACADDM_CHILD_DXGI_FLIP_MODE_VIEW_CLASS` 绘图视图和 `Afx:…:28:` 文档框架。

根因：`tz_mcp/input_bridge.py` 的 `NativeInput.activate_view` 用「面积最大」挑视图（选中 199302），
但按窗口尺寸挑出来的不一定是当前活动图纸；`SetFocus` 之后焦点在另一张图的框架 22088646 上，
`focused()` 校验如实失败。单图纸时两者恰好一致，所以昨天的成功路径没有暴露它。

修法（`tz_mcp/input_bridge.py`）：`SetForegroundWindow` 之后先读当前焦点，**优先选「焦点所在文档框架里的那个视图」**
（`child==focus or IsChild(focus, child)`），只有找不到时才退回面积最大。

```python
self.u.SetForegroundWindow(W.HWND(hwnd)); time.sleep(.25)
focus = self.focus_handle(hwnd)
self.view = None
for _area, child in sorted(candidates, reverse=True):
    if focus and (child == focus or self.u.IsChild(W.HWND(focus), W.HWND(child))):
        self.view = child; break
if self.view is None:
    self.view = max(candidates)[1]
self.u.SetFocus(W.HWND(self.view))
```

修完复测：`OK view 24316406 focused True`（原来固定失败）。之后 s6 才第一次走到真正的超时分支。

## 三、提交期静态校验（s3）：先纠一处误判，再补一个真缺口

第一版 s3 拿 `kind='普通窗'` 当「非法值」，实测却被接受 —— 复查发现 **`普通窗` 本来就在白名单里**
（`tz_mcp/commands.py` 的 opening.create 只认 `普通门`/`普通窗`），是我用例写错，不是校验缺失。

真正的缺口只有一个：`kind='普通门'` + `subkind='普通窗'` 这种**自相矛盾的一对**能通过提交，
要等面板驱动完、对象建出来才由 `parts.py` 抛 `OutcomeUnknown: Panel door type does not match…`——
白耗一次 CAD 交互，还留一个不确定结果。已补最小校验：

```python
if out['kind'] != out['subkind']:
    raise ValueError('kind and subkind must name the same measured type')
```

复测（真实 MCP 工具面）：

| 输入 | 结果 |
|---|---|
| `kind='推拉窗'` | 拒绝：`Only measured ordinary door/window kind strings are supported` |
| `kind='普通门', subkind='普通窗'` | 拒绝：`kind and subkind must name the same measured type` |
| `kind='普通窗', subkind='普通窗'` | 接受（合法路径不受影响） |

带 `$ref` 的 step 仍会跳过 `prepare`（值要等上游产出），这类语义校验只能在执行期做。

## 九、acknowledge 必须写下副作用（同日 11:33 复跑）

§八 的 r5d 是旧契约：`queue_acknowledge(job_id)` 只把任务标成 failed，**图上实际发生了什么没有留下一个字**。
用户指出的问题正在这里：`unknown_outcome` 可能已经画了东西（§四 就抓到 1 根柱子），只写「已确认」等于把
「可能有副作用」悄悄改写成「没有副作用」，下一个人会照着干净的图继续画。

新契约（`tz_mcp/cli.py` `acknowledge`、`tz_mcp/server.py` `queue_acknowledge`）：

1. `side_effects` **必填**：空串、纯空白、`null` 都被拒；
2. 原话进 job 的 `error`：`Operator inspected outcome; original job will not be replayed. Observed side effects: <这句话>`；
3. 另存回执 `<state>/acks/<job_id>.json`：`{job_id, state_before, error_before, side_effects, recorded_at}`；
4. `queue_status` 把整份回执以 `acknowledgement` 字段带回；
5. 仍然 `replayed: false` —— 留档不等于放行重放。
